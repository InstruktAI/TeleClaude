# Demo: history-role-aware

## Medium

CLI — all features are exercised via `telec history` subcommands.

## Validation

### 1. `telec history list` returns session summaries

```bash
telec history list --limit 3
```

Expected: Tabular output with columns session_id, title, timestamps, origin
channel, summary, and message_count. Ordered by most recent first. If no mirrors
exist yet, an empty result message is acceptable.

### 2. `telec history list` filters by project

```bash
telec history list --project TeleClaude --limit 3
```

Expected: Only sessions matching the project filter appear.

### 3. `telec history list` filters by identity

```bash
telec history list --identity maurice@instrukt.ai --limit 3
```

Expected: Only sessions matching the given identity appear.

```bash
telec history list --identity telegram:1285425702 --limit 3
```

Expected: The same explicit filter also works with canonical `source_identity`
values, not just emails.

### 4. Help text includes new `list` subcommand

```bash
telec history --help
```

Expected: Output includes `list` alongside `search` and `show`, with correct
flag descriptions.

### 5. Existing search still works

```bash
telec history search --limit 2 session
```

Expected: Search results appear as before. No regression.

### 6. Existing show still works (if mirrors exist)

```bash
telec history list --limit 1 2>/dev/null | head -3
```

Expected: At least the header or first entry is visible, confirming the command
runs without error.

## Guided Presentation

### Step 1: Progressive disclosure entry point

Run `telec history list --limit 5`. This is the new progressive-disclosure
command — the agent reads session summaries first, picks a relevant session ID,
then drills into the full transcript with `telec history show <session-id>`.

Observe: each row shows a session_id, title, start/end timestamps, origin
channel (telegram/discord/web/terminal), a short summary, and message count.
The summary is generated by the LLM summarizer at mirror-creation time.

### Step 2: Role-based filtering

The list, search, and show commands now resolve the caller's identity via
`resolve_cli_caller_role()` plus the current CLI auth context and apply
role-based filtering:

- **Admin**: sees all sessions.
- **Member**: sees own sessions plus sessions with `visibility='shared'`
  (mirrors the `_filter_sessions_by_role` pattern in `sessions_routes.py`).
- **Customer**: sees only sessions matching their resolved CLI identity.
- **No auth**: existing unfiltered behavior preserved.

This matches the grounded access-control pattern already used in the sessions
API (`_filter_sessions_by_role`), extended to the mirrors layer.

### Step 2b: Explicit identity filter accepts email or source key

The explicit `--identity` filter is broader than caller-role filtering:

- `telec history list --identity maurice@instrukt.ai`
- `telec history list --identity telegram:1285425702`

Both forms work because the list command matches explicit identity filters by
`human_email` OR `source_identity`.

### Step 3: Channel metadata on mirrors

New mirrors created after this change include origin channel metadata from the
session's adapter_metadata: the channel type (telegram, discord, whatsapp, web,
terminal) and channel-specific identifiers (user_id, channel_id, phone_number).

This metadata is visible in the `telec history list` output as the origin
channel column and is stored in the mirror's metadata dict for downstream use.

### Step 4: Session summaries on mirrors

New mirrors include a one-paragraph summary generated at mirror-creation time
using the existing `_call_summarizer` infrastructure (Claude Haiku with
structured outputs). Summary generation is best-effort — if the LLM API is
unavailable, the mirror is still created without a summary. The list command
falls back to the truncated title when no summary exists.
