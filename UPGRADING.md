# Upgrading

This guide holds the steps a running installation cannot take through its forward migrations alone — a new
required setting or credential, an outside system to prepare, a data conversion that needs a backup first. An
installation that follows stable never installs a release beyond its compatibility series on its own: its
installation inspector reads the sections of every version between the active release and the held release,
oldest first, performs their steps in order, then installs the release. A version that needs no such step has no
section.

Each section is headed `## <version>` for the release that ships the change, and its steps are an ordered list
written in the order they must run.

## 0.10.0

1. On Linux hosts, install the libarchive shared library before installing this release, or re-run the full installer (`bin/install.sh`), which now installs it: `libarchive-tools` on Debian/Ubuntu, `libarchive` on Fedora and Arch. The chiptunes corpus extraction decodes the pinned HVSC archive through it. macOS ships the library and needs nothing.
2. For every project on the GitHub workflow store, give the GitHub App mapped to the `builder` role the repository's Contents read permission on that repository: grant it in the App's settings and accept it on the App's installation, before installing this release. The store now reads whether an item's branch is on GitHub before it opens that item's pull request. Without the permission, those pull requests stay owed with the refused credential as their cause and are not opened. An App that already holds Contents read or write needs nothing.
3. Each computer's install sets up TeleClaude's own local Redis by itself (ADR-0143), whether the edge or stable channel installs it or `telec app install` does: it installs the Redis server binary while the previous release serves, then writes its configuration and data under the platform home and its service unit where the operating system keeps user agents or system units, starts it and verifies it before the release's migrations, and writes `REDIS_LOCAL_URL`, `REDIS_LOCAL_USERNAME` and `REDIS_LOCAL_PASSWORD` to the machine `.env`. It never reconfigures another Redis, and removes the block an earlier install of this release line added to the operating system's Redis configuration. On Linux this needs sudo that works without a prompt when the install runs unattended, for the package and the system unit. When the local Redis cannot be set up, the install still completes, the computer keeps its local events on the cluster Redis, and the install log names the reason (ADR-0141); resolve it and install again. A computer with no cluster Redis set gets its own local Redis as its cluster Redis (ADR-0144).
4. The cluster Redis variables are now `REDIS_CLUSTER_URL` and `REDIS_CLUSTER_PASSWORD`. Every install copies the values of `REDIS_URL` and `REDIS_PASSWORD` into them before the configuration migration points `redis.cluster` at them; `REDIS_URL` and `REDIS_PASSWORD` stay in `.env` unused and can be removed after the install.
5. For every project on the GitHub workflow store, give the GitHub App named by its `todos.app` the repository "Variables" permission, read and write, and approve it on the installation. Then, on the computer that should run that project's lifecycle, run `telec projects active-computer set` in the project. Until a project names its active computer, every computer refuses its orchestrator starts, naming the command (ADR-0142).
6. Before installing this release, make sure every computer that serves a project on the GitHub workflow store has installed it, or will before the project's active computer is next restarted. This release keeps each item's artifact versions as native GitHub issue artifacts instead of issue comments and writes a new record format that earlier releases cannot read; the project's active computer converts its items automatically once it runs this release, and a computer still on an earlier release then refuses those items. The repository's organization must also serve GitHub issue artifacts (a private preview); a project whose repository does not is refused with `issue_artifacts_unavailable` until it does. Until an item is converted, writes to it are refused with `awaiting_republication` and can be sent again.
