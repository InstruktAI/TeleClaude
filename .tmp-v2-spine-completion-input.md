## Team-mode dispatch instructions (MANDATORY for the build worker)

Same team-mode pattern as v2-mvp-bootstrap, refined with the lessons from
that MVP retro. Build worker uses TeamCreate + Agent + SendMessage +
TaskUpdate + TeamDelete. Plan worker structures tasks as DAG nodes with

### Build worker (parent) — same as MVP plus these MVP-retro absorptions

1. **Build worker loads `next-build` skill (as standard).** But the skill's
   single-worker linear assumptions don't apply to team-mode dispatch.
   Where the skill says "execute tasks sequentially" or "all plan
   checkboxes [x]" or "per-task commit," reinterpret as: dispatch teammates
   per the DAG; teammates handle commits per their scope; wave completion
   ≈ per-task verification. The team-mode dispatch instructions in this
   input OVERRIDE the skill's default behavior where they conflict.
2. **Pre-spec file-overlap seams in teammate briefs.** Where two parallel
   teammates may touch the same file (e.g., F1 stub + G1 replacement
   pattern from MVP), the build worker writes explicit coordination
   instructions in the teammate briefs telling them to SendMessage before
   either commits.
3. **Wave gating uses cargo directly, not `telec code`.** Between waves,
   build worker runs `cargo build --workspace` and `cargo clippy
   --workspace --all-targets -- -D warnings` directly via Bash, not via
   `telec code lint`. `telec code` is Python+TS only.
4. **Teardown:** SendMessage shutdown_request to each teammate; after all
   shut down, TeamDelete.

### v2 deviations encoded in type signatures (not just docs)

The MVP retro flagged that v2 deviations in `redesign-list.md` weren't
reflected in MVP's type signatures (e.g., "no empty-DRAFT create" was
documented but `WorkflowService::create_todo` signature didn't enforce
it). Fix that pattern here:

- **Tokens: no time-based expiry, revocation is the lifecycle.** The
  signature `issue_session_token(principal, role) -> Token` does NOT
  take an `expiry: Option<Duration>` parameter. The type itself
  enforces the deviation. See `auth-model.md` invariant.
- **Principal cannot be constructed Anonymous via API.** `Principal`
  is `pub` but `Principal::Anonymous` is only reachable via
  `Principal::resolve_anonymous()` — explicit, not the default.
  Resolution functions return `Principal::Human` or
  `Principal::AgentSession` for any authenticated caller; Anonymous is
  the explicit "no auth evidence" outcome.
- **Config service is stateless.** `ConfigService::new(overlay_paths)`
  returns Self; there's no `&pool: PgPool` parameter because config
  doesn't write to Postgres. Config is authored content read at
  startup.

`person > project > global`. Person overrides project overrides global.
Pin this in `crates/config/src/effective.rs` documentation and unit
tests cover the precedence for every field that accepts overrides.

### Session token format

Match v1's existing format. Verify in `teleclaude/core/db/_tokens.py`
and `teleclaude/session_identity.py` for the actual schema (token
string format, issuance metadata, revocation semantics). v2 mirrors
verbatim so v1 and v2 tokens are interchangeable during the parallel

### Internal-event emit posture (REPEATED FOR EMPHASIS)

Per `transport-rules.md` "Emit failure handling":

- Commit-then-emit ordering. State commits first.
- Loud fail on emit error. Return `IdentityError::EmitFailed { ... }`
  with `state_committed: true` semantics.
- NO log-warn-and-swallow. NO outbox table for internal events
  (integration is the only service that uses outbox/inbox patterns).
- Callers are idempotent.

This was the most common reviewer finding in MVP — workers defaulted to
"log warn, don't fail" because the input was vague. Don't be vague here.

## Important v2 deviations from v1 to encode (carry forward from MVP)

- **All inbound is integration's domain** — identity service doesn't
  receive hooks/webhooks; integration normalizes inbound and emits
  events; identity reacts to them via subscription.
- **No process-local mutation hooks** — identity emits Redis events on
  every mutation; subscribers handle their concerns.
- **Single Redis transport** for all events.
- **No `unwrap()`/`panic!()`/`unsafe`** in production paths.
- **No `lazy_static`/`OnceCell`** for service singletons — constructor
  injection only.
- **No mod.rs files**; use `<name>.rs` at parent level.
- **No cross-crate access to internal modules** — use public API only.
- **No HTTP/gRPC between local Rust binaries** — SDK call via crate
  dependency.

## Lessons from MVP to apply (captured from the 2026-05-16 retro)

These adjustments are baked into the input doc above. Listed here for
the build worker's reference so it knows WHY the patterns are what they
are.

1. **Teammates do NOT load `next-build` skill.** The skill's single-worker
   linear assumptions fight team-mode. Rules teammates need are inline in
   the brief template above. Build worker still loads next-build (because
   IT is executing the implementation plan), but reinterprets the skill's
   per-task discipline as per-wave-and-per-teammate.

2. **Multi-worker commits use pathspec'd `/usr/bin/git add`, never
   `telec code commit`.** Workspace-scoped commit sweeps other teammates'
   in-progress files into your commit. MVP authorized the
   `/usr/bin/git add <files> --` workaround mid-build. Same workaround
   here, documented from the start.

3. **`telec code lint/test/format` is Python+TS only.** Use cargo
   directly via Bash. `telec-code-rust-support` (separate todo) will
   close this gap; until then, cargo direct is the documented path.

4. **Pre-spec file-overlap seams between teammates.** F1 stub + G1
   replacement pattern from MVP worked only because the brief told them
   to coordinate via SendMessage. Build worker pre-specs such seams in
   teammate briefs upfront.

5. **`instrukt_ai_logging` is logfmt, not JSON.** v2 doc was wrong;
   `observability-model.md` corrected. The Rust observability crate
   already emits logfmt from MVP.

6. **Per-service error variants pinned in input.** Not just type names —
   every variant of `IdentityError` and `ConfigError` is enumerated
   above. Cuts reviewer-finding density.

7. **`EventEnvelope.principal` is typed `Option<Principal>`, not
   `serde_json::Value`.** MVP shipped with a TODO escape hatch. Don't
   leave escape hatches in inputs; workers run with them.

8. **Emit posture is loud-fail for internal events.** Pinned in
   `transport-rules.md` "Emit failure handling" section. Workers MUST
   NOT swallow emit failures; must return `EmitFailed` errors with
   `state_committed: true` semantics.

9. **v2 deviations in TYPE SIGNATURES not just docs.** Token-no-expiry,
   stateless-config, anonymous-principal-explicit — these deviations
   are encoded in the constructors and method signatures above. Reading
   the signature should be sufficient; redesign-list is documentation.

10. **Complete v1 footprint surfaced upfront.** See
    `services.md` "Complete v1 footprint per service" section. For
    identity and config: footprint is mapped (partial — refine during
    build). For the cutover decision: defer authoritative cutover per
    the safety checklist in `reconstruction-order.md`.

11. **Cutover deferral is the default.** v2 ships parallel-capable. v1
    paths remain authoritative. Future `v2-spine-cutover` (or similar)
