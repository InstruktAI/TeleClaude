# edge-session-creation — Input

Three callers bypass the API edge and call command_service.create_session / run_slash_command directly: integration_bridge.py (spawns integrator), events/cartridges/prepare.py (spawns prepare workers), hooks/whatsapp_handler.py (creates WhatsApp sessions). This violates the Edge Layer architecture — origin_metadata is never assembled, identity resolution is skipped. The fix: all three must call the existing public API endpoints (POST /sessions/run, POST /sessions) via HTTP instead. The daemon authenticates with its session token. The edge assembles origin_metadata. run_slash_command as an in-process method on CommandService gets removed. Also: keep session-level `origin_metadata` separate from per-message typed actor fields throughout the command pipeline to match the layer-ownership architecture.
