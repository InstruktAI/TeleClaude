# ADR-0016: Adopt Graphify CLI as the Codebase Blueprint Engine — ADR

## Context

Agents in the SDLC need the blast radius of a change before they plan it — which callers, importers, subclasses, and tests it can touch. Today they explore ad hoc with grep and miss scope. We evaluated build-vs-buy and assessed Graphify (an AST knowledge-graph builder, tree-sitter, MIT, covering our stack with local, API-free extraction); benchmarks and a source read confirmed it is fast and that its `affected` traversal is a true unbounded-depth reverse-dependency blast radius — whereas its MCP tools measure community-spread risk, not reverse-dependency impact.

## Decision

Adopt the Graphify CLI as-is as the codebase blueprint engine.

- The blueprint is a gitignored `graph.json` plus a freshness manifest, regenerated by the integrator on a successful main pull via the pinned no-LLM code refresh (the LLM extract path is not used).
- **Two thin platform surfaces, not a verb-for-verb wrapper:** one value-add agent primitive, `telec context blueprint affected <changed-files>` (changed files → symbol seeds → `affected` → union, freshness-checked, since Graphify has no file→dependents primitive), plus the integrator generation step. For discovery, agents call `graphify query`/`path` directly. **No MCP server, no 1:1 verb mapping.**
- **The integration seam is the `graph.json` data contract plus the CLI method, not the vendor identity** — another engine that emits the same shape could replace it.

## Consequences

- Near-zero build: extraction, call-graph, and the `affected` traversal come for free; we own only the thin consumption discipline and the generation wiring.
- Local and private: AST-only, no LLM backend, no egress.
- Deliberate, contained coupling: agent-facing docs name `graphify` directly (accepted, not hidden), but only one procedure and the generation step name the tool, both above the stable `graph.json` shape, so a future swap is contained.
- Dependency risk: Graphify is young, fast-moving, and effectively solo-maintained — mitigated by pinning the version and relying on the `graph.json` seam.

## Alternatives Considered

- **Verb-for-verb `telec` wrapper.** Rejected: a 1:1 rename is a maintenance burden and false decoupling — it still breaks when the underlying surface moves.
- **MCP-only consumption.** Rejected: the MCP server is query-only, lacks symbol-level `affected`, and reports community-spread risk rather than blast radius.
- **Build our own extractor now.** Deferred: the `graph.json` seam lets us defer it until/unless Graphify disappoints.
- **The Rust port.** Rejected for now: an independent third-party rewrite with unclear licensing; reconsider only if a native binary or its extra analyses become load-bearing.
