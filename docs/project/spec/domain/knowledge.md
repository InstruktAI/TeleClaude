## What it is

The `knowledge` bounded context owns the platform's structured documentation knowledge layer: the snippet index, the taxonomy that classifies snippets, the selection policy that decides which snippets to load for a given context, and the ingestion pipelines that keep the index in sync with authored sources. It exposes a phase-1 (`index`) and phase-2 (`get`) discovery flow, and a context-selection function that returns a curated set of snippets given inputs like agent, role, slug, taxonomy filters.

This context does NOT own: the authored snippet CONTENT itself (lives on the filesystem under `docs/` — knowledge indexes and serves it but doesn't author it), runtime session orchestration (`agent_runtime`), workflow state (`workflow`), agent artifacts deployment (`agent_artifacts`).

Knowledge is the deliberate alternative to generic RAG. The selection policy is structured, scope-aware, taxonomy-aware, and policy-driven — not vector-similarity-driven. This is the strongest existing platform idea, preserved and codified in v2.

## Canonical fields

### Ubiquitous language

**Snippet**
:  A documentation document under `docs/` that follows the snippet authoring schema. Has frontmatter (id, type, domain, scope, status, etc.) and required H2 sections per its taxonomy.

**Snippet identifier (snippet id)**
:  Unique string identifying a snippet. Convention: `<domain>/<taxonomy>/<short-name>` (e.g., `software-development/policy/testing`).

**Taxonomy**
:  The classification of a snippet by `type`: `principle`, `concept`, `policy`, `procedure`, `design`, `spec`, `third-party`. Each taxonomy has required H2 sections defined in the snippet authoring schema.

**Domain**
:  The knowledge area a snippet belongs to: `general`, `software-development`, `creative`, `customer-relations`, `marketing` (extensible). Derived from the snippet's filesystem path.

**Scope**
:  The visibility/distribution scope of a snippet: `global` (distributed across all projects), `domain` (cross-domain documentation under `general/`), `project` (local to one project). Drives where the snippet lives on the filesystem and where it gets deployed.

**Status** (per Documentation-First Development principle)
:  Snippet lifecycle: `actual` (reflects current reality), `target` (forward design), `mixed`. Default `actual` when omitted.

**Visibility**
:  Access classification: `public` or `internal`. Admin callers see all; non-admin callers see only `public`. Default `internal` when omitted.

**Index**
:  The structured catalog of all snippets — `docs/global/index.yaml`, `docs/project/index.yaml`, `docs/third-party/index.yaml`. Generated by `telec sync`; consumed by `telec docs index/get` and context selection.

**Selection policy**
:  The rules that decide which snippets to load for a given selection request. Inputs: agent, role, slug, taxonomy filters, third-party flag. Output: a curated set of snippet ids with their content (phase 2) or just metadata (phase 1).

**Context selection request**
:  The structured query that drives selection: caller's principal/role, the current todo's slug (if applicable), agent doing the work, taxonomy filters (`--areas`, `--domains`), and progressive-disclosure preferences.

**Progressive disclosure**
:  The principle that snippets activate based on context rather than being loaded en masse. Procedures with `activation_trigger` appear in AGENTS.md's "Activatable Procedures" block; the agent fetches them on-demand via `telec docs get`.

**Three-phase flow**
:  Index first (phase 1, listing) → fetch selected ids (phase 2, content) → fetch any `Required reads (not loaded)` flagged in the previous response (phase 3, dependency expansion). The canonical context-retrieval discipline.

**Baseline manifest**
:  Curated `@`-prefixed list of snippet paths that every agent loads by default — `docs/global/baseline.md` (global) and `docs/project/baseline.md` (project-specific). Inflated into AGENTS.md.

**Third-party snippet**
:  External library/framework documentation snippet under `docs/third-party/` (or `~/.teleclaude/docs/third-party/`). Indexed separately from the taxonomy snippets. Curated; checked against before web-search fallback.

### Aggregates

#### Snippet (aggregate)

- **Root:** `Snippet`
- **Contains:** the source file path; frontmatter (id, type, domain, scope, status, delivered_by, visibility, activation_trigger); the rendered content; required-reads dependency list; see-also soft references.
- **Invariants:**
  - Each snippet has a unique id; duplicate ids across the index are a defect.
  - Snippets follow the taxonomy schema for their `type` (required H2 sections, no extra H2s beyond schema).
  - `status: target` and `status: mixed` REQUIRE non-empty `delivered_by` listing valid roadmap slugs.
  - `status: actual` FORBIDS `delivered_by`.
  - Visibility `internal` snippets are hidden from non-admin callers.
  - Required reads (`@`-references) are expanded inline at build time; missing references fail validation.
- **Identifier:** the snippet id (e.g., `software-development/policy/testing`).
- **Lifecycle:** Created by authoring a file under `docs/`. Mutated by editing the file. Removed by deleting the file. Re-indexed by `telec sync`.

#### Index (aggregate)

- **Root:** `Index` (one per scope: global, project, third-party)
- **Contains:** entries for every snippet in that scope, each entry carrying: id, type, domain, scope, description, visibility, status (only when ≠ actual), delivered_by (only when status is target/mixed), source path, last-indexed timestamp.
- **Invariants:**
  - The index is fully derived from the filesystem; no hand-edits ever.
  - Index entries omit fields with default values (status: actual omitted; delivered_by empty omitted) for diff-cleanness.
  - Re-running `telec sync` on unchanged sources produces byte-identical index output.
  - Index is the single source of truth for "what snippets exist"; `telec docs index/get` queries reach Postgres (v2) or the YAML file (v1).
- **Identifier:** scope (`global` | `project` | `third-party`).
- **Lifecycle:** Built by `telec sync`. Stored in Postgres (`knowledge.snippets_index` in v2) and as `index.yaml` (committed to git for diff visibility).

#### Selection Policy (aggregate)

- **Root:** `SelectionPolicy`
- **Contains:** the set of rules that map a `ContextSelectionRequest` to a list of snippet ids. Rules include: baseline-always-loaded, role-gated visibility, taxonomy filters, progressive-disclosure trigger matching, project-scoped overrides.
- **Invariants:**
  - The selection is deterministic given the same inputs and the same index.
  - Anonymous callers see only `visibility: public` snippets.
  - Admin callers see everything.
  - Filtered queries (`--areas`, `--domains`) narrow the result; unspecified means no filter.
- **Identifier:** the policy is platform-wide; one logical instance.
- **Lifecycle:** The policy itself evolves via `knowledge.taxonomy.updated` events when the rules change (rare). Most policy is hardcoded; the rules are not user-tweakable.

### Domain events emitted

#### `knowledge.snippet.indexed`

- **Producer:** `knowledge`
- **Emitted when:** a snippet is added, updated, or removed during sync and the index changes.
- **Payload:** `snippet_id`, `change_type` (`added` | `updated` | `removed`), `scope`, `last_indexed`, `source_path`.
- **Visibility:** CLUSTER
- **Known consumers:** `frontend` (search index refresh), any agent caching index results.
- **Idempotency key:** `(snippet_id, last_indexed)`.
- **Posture:** `commit-then-emit`.

#### `knowledge.taxonomy.updated`

- **Producer:** `knowledge`
- **Emitted when:** the taxonomy itself changes (new type added, schema rules updated). Rare.
- **Payload:** `change_summary`, `updated_at`.
- **Visibility:** CLUSTER
- **Known consumers:** any cache of selection policy.
- **Idempotency key:** `updated_at`.
- **Posture:** `commit-then-emit`.

### Domain events consumed

#### `config.effective.updated`

- **Producer:** `config`
- **Reaction:** invalidate cached configuration values used by selection (e.g., per-project doc roots, taxonomy filter defaults).
- **Failure handling:** stale config tolerated for one request.

### Use cases

#### UC-KNW-1: Three-phase index → get → expand flow

```
Given an agent needs context on a policy area
When the agent runs `telec docs index --areas policy --domains software-development`
Then knowledge returns snippet metadata (id, type, description, visibility) for matching snippets, with prefix annotations for target/mixed status
And the agent picks the relevant ids
When the agent runs `telec docs get <id1> <id2>`
Then knowledge returns the full content of those snippets
And lists any `Required reads (not loaded)` dependencies the agent should fetch in a follow-up
```

#### UC-KNW-2: Selection respects visibility per principal

```
Given an anonymous caller requests `telec docs index`
Then the result contains only snippets with visibility: public
And `internal` snippets are entirely absent from the response
Given an admin caller requests the same
Then the result contains both public and internal snippets
```

#### UC-KNW-3: Baseline snippets auto-load via AGENTS.md inflation

```
Given the baseline manifest at docs/global/baseline.md references N snippets
And the project's docs/project/baseline.md references M snippets
When `telec sync` runs
Then agent_artifacts inflates AGENTS.md including the inlined baseline snippet content
And every agent session starts with the baseline already in its context
```

#### UC-KNW-4: Progressive disclosure for procedures

```
Given a procedure snippet has activation_trigger: "Use when X happens"
When `telec sync` builds AGENTS.md
Then knowledge marks the procedure for the "Activatable Procedures" block in AGENTS.md
And the procedure does NOT appear in the baseline always-loaded set
And agents fetch the procedure on demand via `telec docs get <procedure-id>` when X happens
```

#### UC-KNW-5: Status-target snippets surface for the assigned worker

```
Given snippet X has status: target with delivered_by: [my-todo]
And the prepare worker for my-todo is preparing context
When the worker runs `telec docs index --target my-todo`
Then knowledge returns X and any other snippets where delivered_by includes my-todo
And the worker has its assigned design surface in one query
```

#### UC-KNW-6: Auto-reconciliation flips target to actual on delivery

```
Given snippet X has status: target with delivered_by: [my-todo]
And my-todo reaches stage: delivered
When `telec sync` runs (manually or as a delivery side-effect)
Then knowledge detects the delivered slug
And rewrites X's frontmatter: status omitted (default actual), delivered_by removed
And the rewrite is staged for commit
And X now reads as `actual` going forward
```

#### UC-KNW-7: Third-party doc lookup before web search

```
Given an agent needs library documentation
When the agent runs `telec docs index --third-party` for the library in question
Then knowledge returns curated third-party snippets if they exist
And the agent uses them (per the Context Retrieval Policy)
And web-search / Context7 are last-resort fallbacks for gaps
```

#### UC-KNW-8: Snippet validation gates commits

```
Given an author edits a snippet with an invalid status (target without delivered_by)
When `telec sync --validate-only` runs (pre-commit hook)
Then knowledge fails validation with a message naming the snippet and the rule
And the commit is blocked until the snippet is fixed
```

### Context map position

- **Customer-Supplier downstream of `identity`** — selection policy uses caller's principal/role to gate visibility.
- **Customer-Supplier downstream of `config`** — reads per-project doc roots, taxonomy defaults.
- **Customer-Supplier upstream to `workflow`** — prepare-orchestrator and build workers consume context selections via knowledge.
- **Open Host Service to any caller** — the index/get/select interface is a stable read surface anything in the platform can use.
- **Anti-corruption layer with v1 (during migration)** — v1 `teleclaude/docs_index.py` (~641 lines) + `teleclaude/context_selector.py` (~958 lines) handle this work today. The v2 ACL preserves the public function signatures consumers depend on; the actual walk/parse/select logic migrates to `crates/knowledge`. Disappears at `v2-knowledge-cutover`.

## Allowed values

- `type` (taxonomy): `principle`, `concept`, `policy`, `procedure`, `design`, `spec`, `third-party`.
- `scope`: `global`, `domain`, `project` (taxonomy snippets); `global`, `project` (third-party).
- `status`: `actual`, `target`, `mixed`.
- `visibility`: `public`, `internal`.
- `change_type` (in indexed event): `added`, `updated`, `removed`.

## Known caveats

- **Source files on filesystem; index in Postgres (v2) or YAML (v1).** Snippet authoring happens in files under `docs/`; the index is derived. Knowledge never modifies snippet sources except via the reconciliation auto-flip pass for `status` / `delivered_by` (per `snippet-status-framework`).
- **Selection policy is hardcoded, not user-tweakable.** Operators don't configure selection rules per-project. This is deliberate — selection is the platform's curation discipline; ad-hoc per-project tweaks would fragment the experience.
- **No vector search.** Selection is structured by taxonomy, scope, and policy. If similarity search becomes useful, it goes through a separate adapter, not knowledge's primary surface.
- **Required reads (`@`-references) are expanded at build time.** This makes the inflated `AGENTS.md` self-contained and avoids dynamic dependency-fetching at session start. Cost: bigger `AGENTS.md`. Benefit: deterministic context.
- **Progressive disclosure trims the always-loaded surface.** Procedures listed under "Activatable Procedures" don't bloat the baseline; they activate when their trigger fires.
- **Third-party docs follow a different schema.** They're indexed separately and have `type: third-party` rather than a taxonomy type.
- **`telec sync` is the only writer for the index.** Hand-editing `index.yaml` is a defect; sync overwrites changes.
