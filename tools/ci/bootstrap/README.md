# Fresh machine bootstrap harness

This harness runs the complete installation proof directly on a fresh GitHub-hosted macOS runner. Before creating any output or starting installation, it requires the GitHub Actions hosted-runner environment, macOS, and the absence of the platform home, daemon socket, and canonical checkout path. A machine that fails any condition is refused.

The candidate checkout is transferred as a Git bundle into the runner user's canonical checkout path. Installation commands run with a small login environment containing the runner user's home, identity, shell, temporary directory, locale, the system login path, and the directory of the hosted job's pinned `uv`, which the installation act needs to build the release. The job process environment, including its repository token, is not passed into those commands. The candidate is installed the way the bootstrap installs a machine: the install act for the exact candidate revision, then convergence from the installed release, which publishes `telec`. The harness checks startup, published documentation, configuration, role and identity probes, repeat installation, service stop and start, post-restart installation, unchanged configuration files, and collected logs.

The seed files contain only `.invalid` addresses. The owner seed is supplied to the installation command through the install-only environment inputs. The people seed drives the configuration and access-scope probes after the service is healthy.
